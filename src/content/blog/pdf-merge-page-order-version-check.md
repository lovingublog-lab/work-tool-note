여러 PDF를 하나로 합치는 작업은 기능 자체보다 어떤 파일을 어떤 순서로 넣었는지가 더 중요합니다. 초안과 승인된 파일이 섞이거나, 부록이 본문 중간에 들어가거나, 필요한 마지막 장이 빠진 상태로 전달되면 병합이 정상적으로 끝나도 결과물은 잘못된 문서가 됩니다.

그래서 PDF 병합은 **기준본 고정 → 문서 순서 결정 → 병합 → 저장된 결과 검수**라는 흐름으로 관리하는 편이 안정적입니다.

## 파일을 합치기 전에 기준본부터 한 번 고정한다

폴더 안에 이름이 비슷한 PDF가 여러 개 있다면 병합 프로그램을 열기 전에 어느 파일을 사용할지 정해야 합니다. 파일명에 ‘최종’이 들어 있다는 이유만으로 최신 상태라고 가정하면 수정본이나 승인본을 놓칠 수 있습니다.

병합 대상마다 사용할 파일을 하나씩 정하고 작업 목록에 파일명을 그대로 적어둡니다. 팀에서 승인 상태를 별도로 관리한다면 파일명과 승인 기록을 함께 대조합니다.

문서 상태가 자주 헷갈린다면 [업무 문서 버전 관리, ‘최종본’ 대신 상태가 보이게 남기는 방법](/blog/document-version-management/)처럼 작업본·검토본·배포본의 역할을 먼저 나누는 방식이 도움이 됩니다.

## 파일명 순서와 실제 페이지 순서는 같은 것이 아니다

파일명을 01, 02, 03처럼 맞추면 선택 순서는 정리하기 쉽습니다. 하지만 파일 안쪽의 페이지가 올바른 순서라는 보장은 없습니다.

표지 뒤에 목차가 와야 하는 문서에서 목차가 별도 PDF라면 단순한 파일명 정렬만으로 원하는 위치가 만들어지지 않을 수 있습니다. 부록이나 첨부자료도 실제 문서 구조에 맞는 위치를 따로 확인해야 합니다.

병합 전에는 파일 단위 순서를 정한 뒤 **각 파일의 첫 장과 마지막 장이 무엇인지** 짧게 확인합니다. 이 두 지점을 알고 있으면 병합 결과에서 문서 경계가 제대로 이어졌는지 빠르게 볼 수 있습니다.

## 문서 경계마다 첫 장과 마지막 장을 확인한다

병합 후 모든 페이지를 처음부터 다시 읽기 전에 오류가 생기기 쉬운 경계를 먼저 확인합니다.

A 문서의 마지막 장 다음에 B 문서의 첫 장이 오는지, 부록이 본문 뒤에 붙었는지, 표지나 의도한 빈 페이지가 예상대로 남아 있는지를 봅니다. 페이지 번호가 인쇄되어 있다면 앞뒤 번호가 자연스럽게 이어지는지도 확인할 수 있습니다.

이 과정은 전체 검수를 대신하는 것이 아니라 **큰 순서 오류를 빠르게 찾는 1차 점검**입니다. 문서 경계가 맞은 뒤 세부 내용을 확인하면 검수 순서가 단순해집니다.

## 세로·가로 페이지와 빈 페이지는 병합 뒤에 다시 본다

여러 문서를 합치면 서로 다른 페이지 크기와 방향이 한 파일에 섞일 수 있습니다. 각각의 원본에서는 자연스럽던 가로 표나 스캔 페이지가 전체 문서 안에서는 갑자기 튀어 보이기도 합니다.

빈 페이지도 원본에서는 양면 인쇄를 위한 의도된 장일 수 있고, 문서 변환 중 생긴 불필요한 장일 수도 있습니다. 따라서 결과물에서 빈 페이지를 발견하면 없애기 전에 왜 있었는지 먼저 확인합니다.

페이지 방향이나 크기가 다르다는 사실 자체가 오류는 아닙니다. 상대방이 화면에서 보는지, 인쇄하는지, 제출용으로 사용하는지에 따라 필요한 상태가 달라질 수 있으므로 전달 목적에 맞춰 판단합니다.

## 병합 작업은 원본과 결과물을 분리한다

순서를 맞추려고 원본 파일을 계속 수정하면 나중에 어느 상태에서 병합을 시작했는지 다시 확인하기 어렵습니다. 병합에 사용할 기준 파일은 그대로 두고 결과물은 별도의 파일로 저장하면 비교할 기준이 남습니다.

실무에서는 원본이 있는 위치와 병합 결과를 두는 위치를 구분하고, 결과물에는 구분되는 파일명을 붙이는 정도면 충분합니다. 목적은 복사본을 많이 만드는 것이 아니라 **원본과 병합 결과의 역할을 섞지 않는 것**입니다.

병합 도중 원본 내용에 수정이 필요하다는 것을 발견했다면 어떤 파일을 기준으로 다시 만들지부터 정합니다. 수정된 파일이 생긴 뒤에는 병합 목록의 파일명과 순서도 다시 맞춰야 합니다.

## 최종 PDF는 저장한 파일을 다시 열어 검수한다

작업 화면에서 순서가 맞아 보여도 저장된 최종 파일을 다시 열어 확인해야 합니다. 실제 전달되는 것은 병합 프로그램의 미리보기가 아니라 저장된 결과물이기 때문입니다.

검수할 때는 다음 순서가 효율적입니다.

1. 예상한 총 페이지 수와 첫 장·마지막 장을 확인한다.
2. 각 문서가 바뀌는 경계의 앞뒤 페이지를 확인한다.
3. 가로 페이지, 빈 페이지, 표와 이미지가 예상대로 보이는지 본다.
4. 필요한 링크나 검색 기능이 있다면 실제 결과물에서 확인한다.
5. 파일명과 문서 안의 날짜·상태가 서로 충돌하지 않는지 확인한다.

보다 넓은 전달본 검수 기준은 [PDF 전달본 검수, 변환 뒤 다시 확인할 지점](/blog/pdf-final-delivery-check/)에서 이어서 볼 수 있습니다.

PDF 병합에서 큰 실수는 합치는 기능을 잘못 쓰는 것보다 **잘못된 기준본을 정확한 순서로 합쳐버리는 것**입니다. 파일을 고르기 전에 기준본을 정하고, 문서 경계를 확인하고, 저장된 결과물을 다시 여는 흐름을 만들면 사용하는 도구가 달라져도 같은 기준으로 작업할 수 있습니다.
