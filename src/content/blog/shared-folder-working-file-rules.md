공유 폴더를 여러 사람이 같이 쓰기 시작하면 파일이 많아서보다 **어느 파일을 지금 수정해야 하는지 모두가 다르게 이해할 때** 문제가 생깁니다. 같은 문서가 여러 위치에 복사되고, 누군가는 예전 파일을 수정하고, 누군가는 새 파일을 올리면서 금세 작업본이 갈라집니다.

해결책은 복잡한 협업 도구보다 먼저 **작업 중인 파일이 머무는 위치와 완료된 파일이 이동하는 위치를 정하는 것**입니다.

## 작업 중인 파일은 한 곳에서만 시작한다

가장 중요한 규칙은 현재 작업본의 위치를 하나로 정하는 것입니다.

예를 들어 프로젝트 폴더 안에 다음처럼 둘 수 있습니다.

- working: 현재 수정하는 파일
- review: 검토 중인 파일
- archive: 지난 버전
- final: 승인·배포 완료 파일

이 구조의 목적은 폴더 수를 늘리는 것이 아니라 “지금 열어야 하는 파일이 어디 있는가”를 바로 알게 만드는 것입니다.

## 개인 PC에 복사한 파일을 새 작업본으로 쓰지 않는다

공유 폴더에서 파일을 내려받아 개인 PC에서 수정한 뒤 다시 올리면 같은 이름의 다른 파일이 생기기 쉽습니다.

가능하면 공유 위치의 파일을 기준으로 작업하고, 별도 복사가 필요한 경우에는 임시 작업본이라는 사실이 이름에서 드러나게 하는 편이 좋습니다.

특히 이메일 첨부나 메신저로 받은 파일을 그대로 새 기준본으로 쓰기 시작하면 공유 폴더의 최신본과 갈라질 가능성이 큽니다.

## 파일명에는 버전과 상태를 함께 남긴다

공유 폴더에서는 파일 위치만큼 이름도 중요합니다.

예를 들어 아래처럼 쓰면 상태를 한눈에 알 수 있습니다.

버전 번호와 상태를 나누는 기준은 [업무 문서 버전 관리 방법](/blog/document-version-management)과 같은 방식으로 잡으면 됩니다.

중요한 것은 ‘최종’, ‘진짜최종’, ‘최종수정’처럼 상황에 따라 뜻이 달라지는 표현을 계속 늘리지 않는 것입니다.

## 같은 파일을 동시에 따로 수정하지 않는다

여러 사람이 같은 문서를 동시에 수정해야 한다면 누가 어느 부분을 맡는지 먼저 나누는 편이 좋습니다.

공동 편집 기능이 있는 서비스라면 하나의 문서 안에서 작업할 수 있지만, 일반 파일을 공유 폴더에서 다룬다면 각자 사본을 만들기보다 작업 순서를 정하는 것이 안전합니다.

예를 들어 한 사람이 본문을 정리한 뒤 검토 상태로 넘기고, 다음 사람이 수정하는 흐름을 정하면 충돌을 줄일 수 있습니다.

## 검토가 시작되면 작업본 위치를 바꾼다

파일이 검토 단계로 넘어갔는데도 계속 working 폴더에 남아 있으면 누군가 다시 수정할 수 있습니다.

그래서 검토가 시작되는 시점에 파일을 review 폴더로 옮기거나 파일명 상태를 review로 바꾸는 편이 좋습니다.

이렇게 하면 “이 파일은 아직 자유롭게 수정해도 되는가?”라는 질문에 폴더 위치나 파일명만으로 답할 수 있습니다.

## 승인된 파일은 덮어쓰지 않는다

완료된 파일은 final 폴더로 옮기고 그대로 보관하세요.

추가 수정이 필요해지면 승인본을 직접 고치기보다 새 작업본으로 복사해 다음 버전에서 다시 시작하는 편이 좋습니다.

이 규칙을 지키면 어떤 파일이 실제로 승인된 결과였는지 나중에 다시 확인하기 쉽습니다.

## 오래된 파일은 삭제보다 보관 위치를 바꾼다

공유 폴더가 복잡해졌다고 오래된 파일을 바로 지우면 과거 변경 내용을 확인하기 어려울 수 있습니다.

대신 현재 작업에 쓰지 않는 파일은 archive로 옮겨 작업 공간에서만 치우는 방식이 관리하기 쉽습니다.

이때 보관 폴더 안에서도 날짜나 버전 순서가 보이도록 파일명을 유지하면 나중에 찾기 편합니다.

## 폴더 설명 문서를 하나 두면 새 사람도 빨리 적응한다

팀 인원이 바뀌거나 외부 협업자가 들어오면 기존 사람만 알고 있는 규칙은 쉽게 무너집니다.

공유 폴더 최상단에 짧은 안내 파일을 하나 두고 아래 정도만 적어도 충분합니다.

- 현재 작업본 위치
- 검토 파일 위치
- 완료 파일 위치
- 파일명 규칙
- 담당자에게 넘기는 시점

길고 복잡한 매뉴얼보다 실제로 지켜야 할 규칙 몇 줄이 더 도움이 됩니다.

## 공유 폴더는 폴더 구조보다 흐름이 중요하다

공유 폴더를 깔끔하게 만들기 위해 폴더를 너무 많이 나누면 오히려 찾기 어려워질 수 있습니다.

핵심은 세 가지입니다.

1. 현재 작업본은 한 곳에 둔다.
2. 검토와 완료 상태가 위치나 이름에서 보이게 한다.
3. 지난 파일은 작업 공간과 분리한다.

공유 폴더 관리의 목적은 보기 좋은 구조가 아니라 **누구나 같은 파일을 기준으로 다음 작업을 시작하게 만드는 것**입니다. 이 기준이 유지되면 파일 수가 늘어도 중복과 덮어쓰기 문제를 크게 줄일 수 있습니다.
