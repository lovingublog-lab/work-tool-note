부서별로 받은 엑셀 파일을 한 장으로 합쳤는데 수량 합계가 달라지거나 날짜 필터가 제대로 작동하지 않는 일이 있습니다. 파일을 복사해 아래에 붙였다는 사실과 **같은 의미의 데이터를 한 표로 합쳤다는 사실**은 다릅니다. 한쪽 파일의 ‘수량’이 개수이고 다른 파일의 ‘수량’이 묶음 수라면 열 이름이 같아도 바로 더할 수 없습니다.

병합 작업을 시작하기 전에 원본 파일마다 **한 행이 무엇을 뜻하는지, 각 열의 단위가 무엇인지, 중복을 구별할 기준이 있는지** 정해 두세요. 이 세 조건이 맞아야 이후 피벗테이블이나 보고서에서도 숫자의 의미를 설명할 수 있습니다.

## 두 파일을 붙이기 전에 행의 의미가 같은가

예를 들어 영업팀의 표는 한 행이 ‘주문 상품 한 건’이고 물류팀의 표는 한 행이 ‘주문번호별 배송 한 건’일 수 있습니다. 주문번호가 같다는 이유로 행을 일대일로 연결하면 한 주문에 여러 상품이나 배송이 있는 순간 금액과 수량이 중복됩니다.

우선 각 파일의 행 단위를 짧게 적어 보세요.

- 주문 상세 파일: 주문번호와 상품번호의 조합이 한 행
- 배송 이력 파일: 주문번호와 배송 차수가 한 행
- 월간 요약 파일: 부서와 월의 조합이 한 행

행의 의미가 다르다면 단순히 아래로 **행 추가(append)** 할 수 없습니다. 특정 키를 기준으로 열을 붙이는 **조인(join)** 작업이 필요한지, 상세 데이터를 먼저 같은 수준으로 집계해야 하는지 판단해야 합니다. 실제 목적이 월별 총량 비교라면 두 상세 표를 원형 그대로 연결하기보다 월·부서 수준으로 집계한 결과를 비교하는 것이 맞을 수 있습니다.

## 열 이름이 달라도 뜻이 같으면 대응표를 만든다

‘고객코드’와 ‘거래처 ID’, ‘매출액’과 ‘금액’이 같은 뜻인지 파일명만 보고 결정하면 위험합니다. 하나는 세금 포함 금액이고 다른 하나는 공급가일 수 있기 때문입니다.

원본을 수정하기 전에 공통 열 이름을 정한 대응표를 별도로 만드세요.

| A 파일 | B 파일 | 통합 열 | 합치기 전 확인 |
| --- | --- | --- | --- |
| 거래처코드 | 고객 ID | customer_id | 같은 식별 체계인지 |
| 출고일 | 처리 날짜 | event_date | 실제로 같은 날짜 기준인지 |
| 중량(kg) | 중량(g) | weight_kg | 단위 변환 필요 |
| 상태 | 진행단계 | status | 허용 상태값의 뜻이 같은지 |

여기서 중요한 것은 대응표가 **이름을 바꾸는 목록이 아니라 정의를 합의하는 문서**라는 점입니다. 원본의 의미가 확인되지 않으면 임의로 공통 열에 넣지 말고 확인 대기 상태로 분리합니다. [스프레드시트 입력 규칙을 열 단위로 표준화하는 방법](/blog/spreadsheet-input-rules-standardize/)에서 설명하는 데이터 정의와 허용값 규칙을 통합 작업에도 적용할 수 있습니다.

## 숫자처럼 보이는 열에서 단위 차이를 찾는다

중량이 1.2와 1200으로 표시된 두 행이 있을 때 하나가 kg이고 하나가 g라면 같은 양일 수 있습니다. 반면 단위를 확인하지 않고 더하면 1201.2라는 잘못된 합계가 생깁니다. 계산 이전에 **원본 단위, 목표 단위, 변환식, 반올림 정책**을 기록해야 합니다.

비슷한 문제는 금액의 통화, 면적 단위, 비율의 표시 방식에서도 발생합니다. 예를 들어 0.15와 15%는 표현만 다른 같은 비율일 수 있지만 15라는 값의 의미가 항상 15%인 것은 아닙니다. 머리글·출력 문서·데이터를 만든 담당자를 통해 의미를 확인해야 합니다.

단위 변환은 새 열에서 수행하고 원본 숫자를 덮어쓰지 마세요. 변환 후에는 표본 몇 행을 역산해서 원래 값과 대응하는지 확인합니다. 반올림 때문에 차이가 생길 수 있는 값이라면 표시용 자릿수와 계산용 원값을 구분합니다.

## 날짜와 식별번호는 계산용 숫자로 바꾸지 않는다

부서마다 ‘2026-10-29’, ‘2026/10/29’, ‘29.10.2026’처럼 날짜가 들어 있다면 화면에 비슷하게 보이더라도 실제 날짜 데이터와 텍스트가 섞여 있을 수 있습니다. 변환 전에 날짜 기준과 지역별 표기 순서를 확인하고, 원본 텍스트를 별도로 보존하세요.

거래처코드 ‘00124’는 앞자리 0이 의미 있는 식별자일 수 있습니다. 숫자로 변환해 124로 만들면 코드 비교에서 오류가 날 수 있으므로 문자로 취급합니다. 빈칸도 모두 같은 의미는 아닙니다. ‘미입력’, ‘해당 없음’, ‘미확정’은 데이터 운영상 다르므로 통합 규칙에서 각각 어떻게 표현할지 정해야 합니다.

이미 셀 형식이 뒤섞여 있다면 [스프레드시트 원본 데이터를 정리할 때의 기본 기준](/blog/spreadsheet-raw-data-cleanup/)처럼 원본 복사본에서 형식을 먼저 검사한 뒤 통합본을 만드세요.

## 병합 결과를 검증하는 숫자는 총합 하나가 아니다

작업이 끝나면 파일마다 원본 행 수, 합쳐진 행 수, 제외된 행 수를 기록해 보세요. 하지만 행 개수가 맞아도 잘못된 키로 연결하면 숫자가 중복될 수 있습니다. 따라서 검증은 최소한 서로 다른 기준으로 수행해야 합니다.

| 검증 대상 | 확인할 질문 |
| --- | --- |
| 행 수 | 원본에서 제외·추가된 행을 설명할 수 있는가 |
| 식별 키 | 중복이 허용되는 구조인지, 예상치 못한 중복인지 |
| 단위별 합계 | 같은 단위로 환산한 뒤 원본 계산과 맞는가 |
| 필수 열 | 빈칸과 잘못된 상태값이 새로 생기지 않았는가 |
| 샘플 대조 | 시작·중간·끝 행에서 원본과 통합본이 대응하는가 |

파일을 받은 순서와 통합한 순서도 남겨야 합니다. 같은 이름의 파일을 새 버전으로 덮어쓰면 나중에 잘못된 수치가 어느 자료에서 왔는지 찾기 어렵습니다. 원본 파일은 읽기 전용으로 보관하고, 변환 규칙이나 계산식을 별도 작업본에 두면 수정 이력을 되짚을 수 있습니다.

## 반복 통합 업무라면 예외 처리 주인을 지정한다

매월 같은 부서에서 자료를 받는다면 파일마다 손으로 열 이름을 고치는 습관부터 줄여야 합니다. 통합 표의 스키마(schema·열 구조)를 한 장의 기준표로 정하고, 신규 열·알 수 없는 상태·단위 없는 수치는 **자동으로 추정하지 않고 확인할 담당자**에게 돌려보내는 규칙을 마련하세요.

모든 자료를 억지로 하나의 표에 채우는 것이 완료 조건은 아닙니다. 의미를 확인할 수 없는 열을 보류하고, 합친 범위와 제외한 이유를 설명할 수 있어야 통합본을 다음 보고서의 기준 데이터로 사용할 수 있습니다. 여러 파일 병합의 품질은 붙여넣기 속도보다 **행 단위·열 의미·검증 결과를 재현할 수 있는지**에서 결정됩니다.
