검토자가 'PDF 7쪽 표를 수정해 주세요'라고 남겼는데 담당자는 보고서 하단에 적힌 7쪽을 고치는 일이 생깁니다. PDF 프로그램의 상단 페이지 표시와 문서 본문에 인쇄된 쪽수가 다르기 때문입니다. **뷰어에서 파일의 몇 번째 페이지인지**와 **보고서에 표시된 인쇄 쪽수**는 서로 다른 기준입니다.

수정 요청에서는 두 숫자 중 하나가 잘못됐다고 지우기보다, 처음부터 **파일 순서와 인쇄 쪽수, 문서 제목 또는 문단 위치**를 함께 남기는 것이 안전합니다. 표지와 목차가 앞에 들어간 자료라면 두 페이지 번호가 다르게 나타나는 것은 흔한 구조적 차이입니다.

## 7번째 PDF 페이지가 본문 4쪽인 이유

예를 들어 파일의 첫 장이 표지, 두 번째 장이 안내, 세 번째 장이 목차이고 네 번째 장부터 본문 1쪽으로 인쇄돼 있다면 **PDF의 일곱 번째 페이지가 본문 4쪽**이 됩니다. 페이지 번호를 세는 기준이 다른 것이지 파일이 손상됐다는 뜻은 아닙니다.

또한 일부 보고서는 머리말을 로마 숫자(i, ii, iii)로 표시하거나 장이 바뀔 때 인쇄 번호를 다시 시작합니다. 부록이 별도로 번호를 갖는 자료도 있습니다. 그래서 'PDF 번호에서 3을 빼면 본문 번호' 같은 계산을 문서 전체에 적용하면 뒤쪽에서 틀릴 수 있습니다.

뷰어의 페이지 표시가 문서 내부의 페이지 레이블을 보여 주는 프로그램도 있어, 상단에 나타나는 숫자를 항상 물리적 페이지 순서라고 단정할 수 없습니다. 어느 페이지를 몇 번째로 세었는지 실제 썸네일 목록과 함께 확인하는 습관이 필요합니다.

## 수정 요청에 남길 위치 표기 하나

'7쪽의 표'보다 다음 표현이 훨씬 명확합니다.

> 기준 파일: 10월 17일 검토본 / PDF 파일의 7번째 페이지 / 본문 인쇄 쪽수 4 / '비용 비교' 표의 둘째 행

실제 작업에서는 표 이름이나 문단의 첫 문장처럼 페이지 번호와 무관하게 찾을 수 있는 **내용 기준점**을 함께 적으세요. 같은 파일을 열었다면 두 사람이 같은 위치로 이동할 가능성이 높아집니다. 화면 캡처를 붙일 때도 표 일부만 자르기보다 제목과 주변 문맥을 포함해야 위치를 찾기 쉽습니다.

파일 이름만으로 기준본이 분명하지 않다면 공유 위치와 수정 기준이 되는 버전도 함께 기재합니다. 이메일에 첨부된 초안과 공유 폴더의 최신본이 다르면 페이지 번호를 완벽히 적어도 의견이 엇갈릴 수 있습니다.

## PDF 파일에 페이지를 추가하거나 합쳤다면

표지나 부록 페이지를 끼워 넣으면 **페이지의 물리적 순서**가 바뀝니다. 반면 본문에 인쇄된 번호는 그대로 남을 수 있습니다. 여러 파일을 병합한 경우에는 각 원본이 가지고 있던 인쇄 쪽수가 반복되기도 합니다. 특히 문서 중간에 추가 페이지가 생겼다면 과거 검토 의견의 'PDF 15번째'라는 위치는 더 이상 맞지 않을 수 있습니다.

수정 전후 버전을 구분해 두고, 병합이나 페이지 삽입이 끝난 **최종 기준본에서 다시 위치를 확인**하세요. 이전 코멘트를 그대로 복사하기보다 제목·표명·문단 내용으로 항목을 찾아 새 위치를 기록해야 합니다. 병합 절차를 설계할 때에는 문서 순서와 검증본을 분리하는 것도 도움이 됩니다.

검토자가 여러 명이라면 [PDF 검토 의견을 하나의 수정 목록으로 모으는 방법](/blog/pdf-review-comments-consolidation/)을 함께 적용해 보세요. 의견을 모으는 순간 기준 파일의 버전과 위치 표기 형식을 고정할 수 있습니다.

## 페이지 번호를 다시 매길 때 생기는 다른 문제

보고서의 인쇄 쪽수가 잘못돼 있다면 원본 문서에서 번호 체계를 수정한 뒤 PDF를 다시 만드는 것이 보통 더 명료합니다. 이미 완성된 PDF의 화면상 페이지 숫자만 바꾸거나 별도의 번호를 덧씌우면 **원래 문서의 목차·교차참조·인쇄 번호**와 불일치가 더 커질 수 있습니다.

인쇄할 목적이라면 실제 종이에 찍힌 페이지 번호도 확인하세요. 양면 인쇄와 빈 페이지 삽입 여부에 따라 종이 묶음에서 찾는 위치가 달라질 수 있습니다. 목차의 쪽수와 본문의 머리말·꼬리말이 일치하는지도 점검 대상입니다.

페이지를 재배치하거나 번호를 고친 다음에는 목차의 주요 항목 세 곳 정도를 실제 페이지에서 찾아 보며 검증하면 좋습니다. 이것은 특정 프로그램의 버튼 위치와 무관하게 적용할 수 있는 확인 방식입니다.

## 의견이 서로 다른 페이지를 가리킬 때의 처리 순서

의견 두 개가 서로 다른 숫자로 같은 대목을 지목한다면 바로 한쪽을 삭제하지 말고 해당 파일 버전, 페이지 기준, 본문 기준점을 비교합니다. 같은 문단을 가리킨다면 하나의 수정 항목으로 묶고 원래 검토자의 표현은 기록에 남깁니다. 다른 문단이라면 비슷한 페이지 번호라는 이유로 합쳐서는 안 됩니다.

다음 회의나 전달 메일에는 '페이지'라는 말만 쓰지 말고 **PDF 파일에서의 순서 / 인쇄된 쪽수** 중 어느 쪽을 뜻하는지 적어 두세요. 자료가 길거나 수정자가 많을수록 이 한 줄이 잘못된 위치를 고치는 재작업을 줄여 줍니다.
