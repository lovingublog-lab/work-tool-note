여러 사람이 쓰는 스프레드시트는 값이 틀려서보다 **같은 뜻을 서로 다른 방식으로 적어서** 망가지는 경우가 많습니다. 완료, 처리완료, Done이 한 열에 섞이고, 날짜가 텍스트와 실제 날짜 값으로 혼재하면 눈으로 볼 때는 비슷해도 필터·피벗·함수에서는 서로 다른 데이터가 됩니다.

입력 규칙을 만들 때는 긴 사용설명서보다 **각 열이 어떤 타입의 값을 받는지, 허용값은 무엇인지, 빈칸은 무슨 뜻인지**를 먼저 정의하는 편이 효과적입니다.

## 열 이름보다 ‘데이터 타입’을 먼저 정한다

같은 열에 날짜와 메모, 숫자와 단위, 이름과 이메일을 섞으면 나중에 정리 비용이 급격히 커집니다. 한 열은 한 종류의 값만 갖는다는 원칙이 기본입니다.

예를 들어 다음처럼 생각할 수 있습니다.

| 열 | 저장할 값 | 피해야 할 입력 |
| --- | --- | --- |
| 주문일 | 실제 날짜 값 | 어제, 10/2쯤 같은 메모 |
| 수량 | 숫자 | 10개, 5박스 |
| 상태 | 정해진 상태값 | 완료, 완료됨, 끝 혼용 |
| 담당자 | 한 가지 식별 방식 | 이름·별명·영문명 혼용 |
| 비고 | 자유 텍스트 | 계산에 필요한 핵심 값 |

단위나 설명은 열 제목이나 별도 열로 분리하면 숫자 계산과 정렬을 그대로 사용할 수 있습니다.

## 식별자는 숫자처럼 보여도 숫자로 다루지 않을 수 있다

사번, 주문번호, 우편번호처럼 계산하지 않는 값은 겉보기에는 숫자여도 ‘수치’가 아니라 **식별자**입니다. 앞자리 0이 사라지거나 지수 표기로 바뀌면 원래 값을 잃을 수 있습니다.

이런 열은 처음부터 텍스트로 다룰지 결정해야 합니다. 반대로 금액·수량처럼 합계나 평균을 계산할 값은 숫자로 저장하고 통화 기호나 단위는 표시 형식으로 처리하는 편이 안정적입니다.

## 상태값은 업무 흐름을 반영하되 개수를 늘리지 않는다

상태 열은 자유 입력보다 선택값이 잘 맞는 대표적인 영역입니다. 하지만 선택지를 지나치게 세분하면 오히려 사용자가 비슷한 값을 임의로 고르게 됩니다.

예를 들어 대기 → 진행중 → 검토중 → 완료 정도로 실제 업무 단계가 구분된다면 충분할 수 있습니다. 거의완료, 완료예정, 최종확인중처럼 해석이 겹치는 값이 늘어나면 필터는 정교해지는 대신 데이터 의미가 불안정해집니다.

새 상태를 추가할 때는 “기존 상태로는 어떤 의사결정을 할 수 없어서 필요한가”를 먼저 확인하는 편이 좋습니다.

## 빈칸은 데이터가 아니라 ‘의미’를 가진다

협업 시트에서 빈칸이 가장 위험한 이유는 사람마다 다르게 해석하기 때문입니다. 아직 입력하지 않은 것인지, 해당 없음인지, 확인했지만 값이 없는 것인지 알 수 없으면 집계 결과도 애매해집니다.

업무상 구분이 필요하다면 미확인, 해당없음처럼 의미가 있는 값을 따로 둡니다. 다만 모든 빈칸을 문자열로 채울 필요는 없습니다. 계산이나 분석에서 실제 결측값으로 다뤄야 하는 열이라면 빈칸을 유지하고, 그 의미를 열 설명에 적는 방식이 더 적절할 수 있습니다.

## 날짜는 표시 형식보다 ‘실제 날짜 값인지’가 중요하다

화면에서 2026-10-02로 보여도 내부적으로 텍스트라면 날짜 계산이나 기간 필터에서 예상과 다르게 동작할 수 있습니다. 날짜 열은 입력 후 정렬하거나 날짜 함수를 적용해 실제 날짜 값으로 인식되는지 확인해보세요.

팀에서 입력 형식을 하나로 정하는 것도 중요하지만, 더 중요한 것은 복사·붙여넣기나 외부 시스템에서 들어온 값이 같은 타입으로 유지되는지입니다.

## 입력 규칙은 안내문보다 검증 기능으로 강제하는 편이 낫다

반복되는 상태값이나 담당자, 분류값은 사용자가 기억해서 입력하게 하기보다 드롭다운·데이터 유효성 검사 같은 기능으로 제한하는 편이 실수가 적습니다.

다만 규칙을 너무 강하게 걸면 예외 업무를 기록하지 못할 수 있습니다. 예외가 실제로 존재한다면 자유 입력을 허용할 별도 비고 열을 두고, 핵심 집계 열은 표준값을 유지하는 식으로 역할을 나누는 것이 좋습니다.

## 원본 입력과 계산 결과를 같은 열에 섞지 않는다

사용자가 직접 입력하는 값과 수식으로 만들어지는 값이 섞이면 누가 무엇을 수정해야 하는지 불분명해집니다. 가능하면 원본 입력 열, 파생 계산 열, 보고용 요약을 구분하고 수식 열은 실수로 덮어쓰지 않게 보호하는 방식을 고려하세요.

이미 값이 뒤섞여 있다면 [스프레드시트 원본 데이터를 정리할 때 먼저 맞춰야 할 기준](/blog/spreadsheet-raw-data-cleanup/)에서 사후 정리 순서를 확인할 수 있습니다. 하지만 반복해서 쓰는 시트라면 사후 정리보다 입력 단계의 표준화가 비용이 훨씬 적습니다.

좋은 입력 규칙은 ‘모든 경우를 설명하는 문서’가 아니라 **열을 보는 순간 어떤 값을 넣어야 하고, 어떤 값은 넣으면 안 되는지 판단할 수 있는 구조**입니다. 날짜·상태·식별자·담당자·빈칸의 의미부터 정리하면 이후 필터와 집계가 훨씬 예측 가능해집니다.
