여러 사람이 같은 스프레드시트를 쓰면 가장 비싼 오류는 오타 하나가 아니라 **같은 의미가 여러 형태로 저장되는 것**입니다. “완료”, “완료됨”, “처리완료”가 섞이면 사람 눈에는 같아 보여도 필터와 집계에서는 다른 값이 됩니다.

입력 규칙을 만들 때는 문서 사용법을 길게 적기보다 **각 열이 어떤 데이터 타입과 허용값을 가져야 하는지**를 먼저 정하는 편이 효과적입니다.

## 열마다 ‘의미·형식·허용값’을 한 줄로 정의한다

간단한 데이터 사전(data dictionary)을 만들면 협업 기준이 분명해집니다. 거창한 별도 문서가 아니라 열 이름 옆 메모나 안내 시트 한 장이면 충분합니다.

예를 들어 다음처럼 정할 수 있습니다.

| 열 | 의미 | 허용 형식 |
|---|---|---|
| 요청일 | 요청이 접수된 날짜 | 실제 날짜 값 |
| 상태 | 현재 처리 단계 | 대기 / 진행 / 완료 / 보류 |
| 담당자 | 현재 책임자 | 팀에서 정한 한 가지 이름 표기 |
| 수량 | 계산 대상 개수 | 숫자만 |
| 메모 | 예외 설명 | 자유 입력 |

이렇게 정의하면 “무엇을 입력할지”와 “어떻게 입력할지”를 분리할 수 있습니다.

## 상태값은 자유입력보다 ‘통제된 값’으로 만든다

상태 열처럼 선택지가 제한된 값은 데이터 검증이나 드롭다운을 사용하면 오타와 표현 차이를 줄일 수 있습니다. 중요한 점은 선택지를 많이 만드는 것이 아니라 **업무 판단에 실제로 필요한 상태만 남기는 것**입니다.

예를 들어 “검토중”, “검토 중”, “확인중”이 모두 같은 단계라면 하나의 표준값으로 합치는 편이 낫습니다. 반대로 “보류”와 “완료”처럼 업무 의미가 다른 값은 편의상 합치면 안 됩니다.

## 날짜는 표시 모양보다 실제 데이터 타입을 맞춘다

셀에 2026-10-02처럼 보인다고 모두 날짜 데이터인 것은 아닙니다. 일부 행이 텍스트로 저장되면 정렬, 기간 필터, 날짜 계산에서 예상과 다른 결과가 생길 수 있습니다.

입력 열에서는 실제 날짜 값으로 저장하고 표시 형식은 한 가지로 통일합니다. 외부 시스템에서 붙여넣은 데이터라면 몇 개 셀을 샘플로 골라 날짜 계산이 정상적으로 되는지 확인하는 것이 좋습니다.

## 빈칸, 0, ‘해당 없음’을 같은 값으로 취급하지 않는다

분석할 때 가장 자주 문제가 되는 부분 중 하나가 결측값입니다. **결측값은 아직 값이 없거나 알 수 없는 상태**를 뜻합니다.

- 빈칸: 아직 입력하지 않음
- 0: 측정하거나 계산한 결과가 실제로 0
- 해당 없음: 이 행에는 그 항목 자체가 적용되지 않음

세 상태를 모두 빈칸으로 두면 나중에 누락과 정상 상태를 구분하기 어렵습니다. 반대로 모든 빈칸을 0으로 채우면 평균이나 합계 해석이 달라질 수 있습니다.

## 숫자와 단위는 분리한다

수량 열에 “10개”, 비용 열에 “3만원”처럼 문자와 숫자를 함께 넣으면 합계, 정렬, 차트에서 다시 정제해야 합니다. 계산할 열은 숫자만 저장하고 단위는 열 제목이나 별도 열에서 관리합니다.

예를 들어 “수량”에는 10, “단위”에는 개를 넣으면 나중에 박스·세트처럼 다른 단위가 섞였을 때도 구조를 유지할 수 있습니다.

## 행을 구분할 고유 식별자가 필요한지 판단한다

고객명, 프로젝트명, 요청 제목처럼 중복될 수 있는 값만으로 행을 찾으면 수정·병합 과정에서 다른 행을 잘못 건드릴 수 있습니다. 반복적으로 업데이트되는 목록이라면 요청번호나 작업 ID처럼 **행을 고유하게 식별할 값**을 두는 것이 유용합니다.

식별자는 사람이 보기 좋은 이름과 역할이 다릅니다. 이름이 바뀌어도 같은 대상을 추적할 수 있어야 합니다.

## 입력 열과 계산 열을 섞지 않는다

수식이 있는 열에 사람이 직접 값을 덮어쓰면 어느 행부터 계산 방식이 달라졌는지 찾기 어려워집니다. 가능하면 사용자가 입력하는 열과 수식으로 계산되는 열을 시각적으로 구분하고, 계산 열은 실수로 편집되지 않게 보호하는 방법을 검토하세요.

도구마다 보호 기능은 다르므로 구체적인 메뉴는 사용하는 서비스의 공식 도움말을 확인하는 것이 좋습니다.

## 이미 뒤섞인 데이터는 ‘표준값 표’부터 만든다

기존 데이터가 엉켜 있다면 한 번에 전부 손으로 고치기보다 어떤 값을 어떤 표준값으로 바꿀지 매핑표를 먼저 만듭니다.

예:
- 완료됨 → 완료
- 처리완료 → 완료
- 진행 중 → 진행
- 진행중 → 진행

원본 파일은 보존하고 작업본에서 정리하는 방식은 [스프레드시트 원본 데이터를 정리할 때 먼저 맞춰야 할 기준](/blog/spreadsheet-raw-data-cleanup/)과 함께 보면 좋습니다.

입력 규칙이 제대로 만들어졌는지는 설명 문서의 길이가 아니라 **새 데이터가 들어와도 필터·집계·정렬이 추가 정리 없이 그대로 동작하는지**로 판단할 수 있습니다.
