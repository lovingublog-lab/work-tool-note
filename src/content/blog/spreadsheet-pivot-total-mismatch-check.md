피벗테이블을 만들었는데 화면에 나온 총합이 원본 표에서 직접 계산한 숫자와 다르면 수식 오류부터 의심하기 쉽습니다. 하지만 실제로는 **두 숫자가 같은 행, 같은 필터, 같은 집계 방식으로 계산되고 있는지**가 먼저 확인할 부분입니다.

피벗테이블은 원본을 그대로 복사하는 표가 아니라 데이터를 묶어서 다시 집계하는 도구입니다. 따라서 원본의 합계와 비교하려면 “어떤 값을 어떤 단위로 모았는가”부터 맞아야 합니다.

## 첫 번째 질문은 ‘무슨 숫자가 같아야 하는가’다

원본에서 금액 열을 더한 값과 피벗의 금액 합계를 비교하는 것은 비교 기준이 명확합니다. 하지만 피벗이 주문 건수를 보여주는데 원본에서는 고객 수를 세고 있다면 숫자가 다른 것이 정상입니다.

피벗의 값 영역이 다음 중 무엇인지 확인합니다.

- 합계
- 개수
- 평균
- 최댓값·최솟값
- 고유 항목 수처럼 중복을 제외한 집계

특히 숫자 열이라고 생각했는데 일부 값이 문자로 저장되어 있으면 합계 대신 개수로 처리되거나 일부 행이 숫자로 계산되지 않는 경우가 있습니다.

따라서 차이를 고치기 전에 **피벗의 열 제목과 값 집계 방식이 내가 비교하려는 숫자와 같은 의미인지**부터 확인해야 합니다.

## 보이지 않는 필터 하나가 전체 합계를 바꾼다

피벗테이블에는 행·열 필터 외에도 페이지 필터, 슬라이서, 날짜 그룹, 특정 항목 제외처럼 화면에서 바로 눈에 띄지 않는 조건이 걸릴 수 있습니다.

원본에서는 모든 행을 더했는데 피벗은 특정 부서나 기간만 포함하고 있다면 합계가 다른 것은 당연합니다.

차이를 찾을 때는 피벗 결과를 보며 필터를 하나씩 해제하기보다 **현재 적용된 조건을 적어 놓고 원본에도 같은 조건을 적용해 비교**하는 것이 좋습니다. 그래야 피벗이 잘못된 것인지, 비교 기준이 달랐던 것인지 구분할 수 있습니다.

보고서 숫자와 원본을 맞추는 더 넓은 검수 기준은 [보고서 숫자가 원본 표와 다를 때, 기준일·필터·집계 범위를 맞추는 법](/blog/report-numbers-source-data-mismatch-check/)에서도 같은 방식으로 적용할 수 있습니다.

## 새로 추가한 행이 원본 범위 밖에 있을 수 있다

원본 데이터 아래에 새 행을 추가했는데 피벗 숫자가 그대로라면 피벗이 참조하는 범위를 확인할 필요가 있습니다.

일부 스프레드시트 도구에서는 피벗 원본이 특정 셀 범위로 고정되어 있을 수 있습니다. 예를 들어 기존 데이터가 1행부터 500행까지였는데 501행 이후를 추가했다면 새 데이터가 자동으로 포함되지 않는 구조일 수 있습니다.

원본 범위를 볼 때는 마지막 행만 확인하지 말고 **필요한 열이 모두 같은 범위에 들어 있는지**도 봅니다. 중간에 빈 열이나 별도 표가 끼어 있으면 의도한 데이터 영역과 실제 참조 영역이 달라질 수 있습니다.

새 데이터를 자주 추가하는 업무라면 원본 구조를 일정하게 유지하는 것이 중요합니다. [스프레드시트 원본 데이터를 정리할 때 먼저 맞춰야 할 기준](/blog/spreadsheet-raw-data-cleanup/)처럼 한 행이 한 건을 나타내고 열 의미를 고정해두면 피벗 범위도 관리하기 쉬워집니다.

## 숫자처럼 보이는 문자와 빈칸을 따로 본다

원본 셀에 1000이 보인다고 항상 숫자 1000으로 저장된 것은 아닙니다. 외부 시스템에서 복사한 값에는 앞뒤 공백이나 문자 형식이 섞여 숫자로 계산되지 않을 수 있습니다.

피벗에서 특정 항목만 합계가 작다면 그 항목의 원본 행 몇 개를 확인해 봅니다. 같은 열에서 어떤 셀은 숫자로, 어떤 셀은 문자로 들어 있다면 집계 결과가 달라질 수 있습니다.

빈칸도 마찬가지입니다. 빈칸이 0을 뜻하는지, 미입력인지, 해당 없음인지 정의가 없으면 평균이나 개수 집계에서 해석이 달라질 수 있습니다.

이 문제는 피벗 안에서 억지로 보정하기보다 **원본 열의 데이터 형식을 먼저 통일한 뒤 다시 집계**하는 편이 재사용성이 높습니다.

## 중복 행이 있으면 합계는 맞아 보여도 의미가 틀릴 수 있다

피벗 합계가 원본 단순 합계와 정확히 같더라도 결과가 항상 올바른 것은 아닙니다. 원본에 같은 거래나 작업이 두 번 들어 있다면 두 표는 같은 잘못된 값을 보여줄 수 있습니다.

반대로 피벗에서 고객별 매출을 보는데 원본에 한 주문이 상품별 여러 행으로 나뉘어 있다면 주문 수와 행 수를 같은 것으로 세면 차이가 생깁니다.

그래서 피벗을 검수할 때는 “합계가 맞는가”와 별개로 **한 행이 무엇을 의미하는지**를 확인해야 합니다. 주문 한 건인지, 상품 한 줄인지, 고객 한 명인지가 정해져야 개수와 고유 개수를 올바르게 선택할 수 있습니다.

## 갱신 문제인지 확인할 때는 원본 한 줄로 시험한다

원본을 수정했는데 피벗이 이전 숫자를 계속 보여준다면 새로고침이나 재계산이 필요한 상태일 수 있습니다. 이때 많은 셀을 한꺼번에 바꾸지 말고 영향이 분명한 테스트 행 하나로 확인하는 방법이 좋습니다.

예를 들어 특정 항목에 작은 테스트 값을 추가한 뒤 피벗을 갱신했을 때 해당 그룹의 합계가 예상한 만큼 변하는지 봅니다. 변하지 않는다면 원본 범위나 갱신 상태를 다시 확인할 근거가 생깁니다.

테스트가 끝나면 임시 행을 제거하고 최종 데이터를 다시 갱신합니다. 실제 업무 값에 임의 숫자를 덮어쓰는 방식으로 시험하면 나중에 원복 여부를 놓칠 수 있으므로 별도 테스트 행이나 복사본을 쓰는 편이 안전합니다.

## 차이를 찾을 때는 작은 그룹 하나로 범위를 줄인다

전체 합계가 수십만 행에서 몇 퍼센트 차이 난다고 전체 데이터를 처음부터 훑는 것은 비효율적입니다. 피벗의 행 항목 중 차이가 의심되는 한 부서, 한 날짜, 한 상품군처럼 작은 그룹을 골라 원본과 비교합니다.

작은 범위에서 **행 수 → 필터 → 값 형식 → 중복 → 집계 방식**을 맞추면 차이가 생긴 지점을 더 빨리 찾을 수 있습니다.

피벗테이블 합계 불일치는 수식을 다시 만드는 문제라기보다 **비교 대상의 정의를 맞추는 문제**인 경우가 많습니다. 같은 원본 범위, 같은 필터, 같은 집계 단위가 확인된 뒤에도 숫자가 다를 때 비로소 도구의 갱신 상태나 계산 문제를 더 깊게 보는 순서가 효율적입니다.
