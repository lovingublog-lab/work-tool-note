업무 파일을 다른 사람에게 넘길 때 가장 큰 문제는 파일 개수가 많아서가 아니라 **어떤 파일이 지금 기준의 최종본인지, 다음에 무엇을 해야 하는지 바로 알기 어렵다는 것**입니다.

폴더를 통째로 전달하는 것만으로는 인수인계가 끝나지 않습니다. 받는 사람이 파일을 열기 전에 구조를 이해할 수 있도록 최종본, 진행 중 자료, 참고자료를 구분하고 짧은 설명을 함께 남기는 편이 훨씬 안전합니다.

## 먼저 전달 대상 폴더를 하나로 모은다

업무 파일이 여러 위치에 흩어져 있다면 공유 전에 전달 기준 폴더를 하나 정합니다.

메일 첨부, 개인 바탕화면, 다운로드 폴더, 팀 공유폴더에 같은 문서가 나뉘어 있으면 받는 사람은 어떤 파일을 기준으로 봐야 할지 판단하기 어렵습니다.

먼저 실제로 이어서 작업할 파일만 한 위치에 모으고, 중복 파일은 기준본을 확인한 뒤 정리합니다.

프로젝트 폴더 구조 자체가 복잡하다면 [업무 폴더가 복잡해질 때 프로젝트별 구조를 단순하게 만드는 법](/blog/project-folder-structure/)처럼 상위 구조부터 정리한 뒤 전달하는 편이 좋습니다.

## 최종본과 작업중 파일을 같은 이름으로 두지 않는다

인수인계 과정에서 가장 위험한 상황은 비슷한 이름의 파일이 여러 개 있는데 어느 것이 최신인지 모르는 경우입니다.

예를 들어 `보고서_최종`, `보고서_최종2`, `보고서_진짜최종`처럼 사람이 기억으로 구분해야 하는 이름은 전달 이후 혼란이 생기기 쉽습니다.

파일명에는 날짜, 버전, 상태 중 필요한 요소를 일정한 방식으로 넣고, 최종 제출본과 편집 가능한 작업본을 명확히 구분하세요.

기존 파일명 규칙을 정리하려면 [업무 파일 이름을 매번 다르게 짓지 않게 만드는 규칙](/blog/work-file-naming-rules/)을 같이 적용할 수 있습니다.

## 작업 중인 파일은 '다음 행동'을 같이 적는다

진행 중 문서를 그냥 넘기면 받는 사람이 내용을 읽고 남은 일을 다시 추론해야 합니다.

파일 옆 설명이나 인수인계 메모에 어디까지 완료됐는지, 어떤 항목을 다시 확인해야 하는지, 누구의 답변을 기다리는지, 다음 마감이 언제인지 정도를 짧게 남기는 편이 좋습니다.

중요한 것은 긴 배경 설명보다 **다음 사람이 바로 시작할 수 있는 한두 문장**입니다.

## 참고자료는 작업 파일과 같은 층에 섞지 않는다

회의자료, 원본 데이터, 참고 이미지, 이전 버전처럼 당장 수정할 파일이 아닌 자료는 별도 폴더로 분리하는 편이 좋습니다.

작업 파일과 참고자료가 한 폴더에 섞이면 파일 수가 많아지고, 검색 결과에서도 비슷한 문서가 함께 나타납니다.

예를 들어 `01_working`, `02_final`, `03_reference`, `99_archive`처럼 단순하게 나눌 수 있습니다. 폴더 이름 자체보다 중요한 것은 받는 사람이 열자마자 어디부터 봐야 하는지 알 수 있게 하는 것입니다.

## 링크로 전달할 때는 권한까지 확인한다

공유폴더 링크를 보냈는데 상대가 열 수 없다면 인수인계가 멈춥니다.

링크를 전달하기 전에는 실제 대상 계정이 접근 가능한지, 편집이 필요한 사람에게 편집 권한이 있는지, 외부 공유가 불필요하게 넓게 열려 있지 않은지 확인합니다.

공유폴더를 여러 사람이 함께 쓰는 환경이라면 [공유 폴더에서 작업 파일이 꼬이지 않게 운영하는 규칙](/blog/shared-folder-working-file-rules/)도 도움이 됩니다.

## 개인 메모와 임시 파일은 전달 전에 한 번 걸러낸다

업무 중에는 스크린샷, 임시 메모, 테스트 파일, 개인용 사본이 자연스럽게 생깁니다. 이것까지 전부 넘기면 핵심 자료를 찾기 어려워집니다.

전달 전에 실제 업무 기록으로 남겨야 하는 자료, 참고용으로 필요할 수 있는 자료, 개인 임시파일이라 삭제해도 되는 자료로 나눠봅니다.

다만 기록 보존 규칙이 있는 조직이라면 임의로 삭제하지 말고 해당 정책을 따르는 것이 우선입니다.

## 인수인계 메모는 파일 목록이 아니라 출발점이어야 한다

좋은 인수인계 메모는 폴더 안 파일을 전부 나열하지 않습니다. 대신 받는 사람이 어디서 시작해야 하는지를 알려줍니다.

기준 폴더 위치, 현재 최종본 파일명, 아직 진행 중인 항목, 다음 마감 또는 확인 일정, 관련 담당자나 참고 위치 정도면 충분한 경우가 많습니다.

파일 목록은 폴더에서 볼 수 있지만, 업무의 현재 상태는 설명이 없으면 알기 어렵습니다.

## 전달 후에는 상대가 열어봤는지만 확인한다

파일을 보낸 뒤 장황한 설명을 다시 반복하기보다 상대가 폴더와 핵심 파일을 정상적으로 열 수 있는지만 확인하는 것이 좋습니다.

접근 권한, 깨진 링크, 누락된 첨부처럼 기술적인 문제가 없으면 그다음부터는 전달받은 사람이 메모를 기준으로 이어서 작업할 수 있습니다.

업무 파일 인수인계의 목표는 깔끔한 폴더를 보여주는 것이 아닙니다. **다음 사람이 파일 위치와 현재 상태를 빠르게 이해하고 바로 이어서 일할 수 있게 만드는 것**이 핵심입니다.
